# OpenCable — Working Memory

> Internal working notes for future OpenCable tasks. This file is maintained so an implementation session can quickly recover the current architectural state without redoing the same analysis.

## Current objective

Adapt hp-sim5 to OpenCable while following the original hp-sim5 architecture. Do **not** bypass the native USD → setupScene → ECS → RenderSystem pipeline.

Immediate visual task:
- OpenCable carriage is a rigid square: **350 × 350 mm**.
- hp-sim5 simulation coordinates are in **meters**: 350 mm = **0.350 m**.
- The four carriage corners are the future pulley locations.
- Preserve the existing OpenCable USD cables, spools, pinholes, joints and paths unless a later task explicitly changes them.
- Z is independent and is not part of the XY belt kinematics.

## Architecture already established

### Scene loading
`hp-sim/app/appBootstrap.js` selects a USD scene and calls the original slideprinter scene setup. OpenCable is already present in the machine selector as `opencable_8belt.usda`. Do not add it again.

### USD → ECS
`example_apps/js/slideprinter/setupScene.js`:
- discovers `CablePathAPI`, `CableJoint`, `DistancePhysicsJoint`, and `RigidGroup` prims;
- creates ECS entities for tagged Spools, Anchors, Pinholes/Attachments;
- builds `RigidGroupComponent` from `rigidGroup:members`;
- reads `rigidGroup:renderIndices` and passes the resulting render segments into `RigidGroupComponent`.

### Rendering
`setupScene.js` imports the native:
`../flipper/renderSystem.js`

The current carriage outline is therefore **not an explicit USD `Carriage`/`Cube` prim**. The visible rigid-group outline is generated by the renderer from the rigid-group members/render segments.

This is important: previous attempts that created a separate renderer or monkey-patched `RenderSystem.run()` were rejected because they bypass the developer's architecture. Do not repeat that approach.

## Geometry constraints

Do not invent dimensions, offsets, chamfers, hole positions, or SVG coordinates.

The user's explicit geometry facts are:
- carriage = 350 × 350 mm;
- drawing is authored in mm;
- hp-sim5 uses 1 simulation unit = 1 meter;
- drawing corners represent pulley locations.

The raw SVG source has not been reliably available in the repository/file environment. Therefore any future exact contour/hole coordinate must come from the actual source file, not from inference or generated images.
