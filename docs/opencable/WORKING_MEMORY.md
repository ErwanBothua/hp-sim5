## Current objective

Adapt hp-sim5 to OpenCable while following the original hp-sim5 architecture. Do **not** bypass the native USD → setupScene → ECS → RenderSystem pipeline.

Immediate visual task:
- OpenCable carriage is a rigid square: **350 × 350 mm**.
- hp-sim5 simulation coordinates are in **meters**: 350 mm = **0.350 m**.
- The four carriage corners are the future pulley locations.

## Architecture already established

### Scene loading
`hp-sim/app/appBootstrap.js` selects a USD scene and calls the original slideprinter scene setup. OpenCable is already present in the machine selector as `opencable_8belt.usda`. Do not add it again.

### USD → ECS
`example_apps/js/slideprinter/setupScene.js`:
- discovers `CablePathAPI`, `CableJoint`, `DistancePhysicsJoint`, and `RigidGroup` prims;
- creates ECS entities for tagged Spools, Anchors, Pinholes/Attachments;
- builds `RigidGroupComponent` from `rigidGroup:members`;
- reads `rigidGroup:renderIndices` and passes the resulting render segments into `RigidGroupComponent`.

### Rendering
`setupScene.js` imports the native:
`../flipper/renderSystem.js`

The carriage outline is generated by the native rigid-group rendering mechanism. The original Hexagon scene demonstrates the intended pattern: a `RigidGroup` carries a member list and a `rigidGroup:renderIndices` string that defines the visible outline.

This is important: previous attempts that created a separate renderer or monkey-patched `RenderSystem.run()` were rejected because they bypassed the developer's architecture. Do not repeat that approach.

### Carriage implementation completed
`public/usd_scenes/opencable_8belt.usda` now uses the native rigid-group render representation:
- exactly four carriage attachment members;
- 350 × 350 mm physical extent represented as ±0.175 m around the carriage center;
- SVG corner convention is respected: **A = top-left, B = top-right, C = bottom-right, D = bottom-left**;
- `rigidGroup:renderIndices = "[0,1,2,3,0]"` closes the four-corner outline;
- cable joints/path definitions remain present and unchanged in structure.

The relevant source logic was verified against `slideprinter_hexagon.usda`, which uses `rigidGroup:renderIndices` for the visible rigid outline, and against `setupScene.js`, which parses that field and constructs `RigidGroupComponent`.

## Geometry constraints

Do not invent dimensions, offsets, chamfers, hole positions, or SVG coordinates.

The user's explicit geometry facts are:
- carriage = 350 × 350 mm;
- drawing is authored in mm;
- hp-sim5 uses 1 simulation unit = 1 meter;
- drawing corners represent pulley locations;
- SVG corner labels: A top-left, B top-right, C bottom-right, D bottom-left.

The raw SVG source has not been reliably available in the repository/file environment. A File Library derivative contains a description of the technical drawing, but it is not treated as authoritative raw SVG geometry. Therefore any future exact contour/hole coordinate must come from the actual source file, not from inference or generated images.
